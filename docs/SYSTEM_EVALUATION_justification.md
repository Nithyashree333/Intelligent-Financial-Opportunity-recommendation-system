The system supports the natural language retrieval
Evaluation against `labelled_examples.csv` yields an overall Hit Rate@5 of 0.75, successfully retrieving relevant results for 6 out of 8 queries. For instance, standard queries like "I have ₹2 lakh, want medium risk..." scored a perfect hit, but the system failed on the query "Budget is ₹1 lakh, high risk is acceptable, and I can stay invested for 3 to 5 years." This specific failure occurred because the strict hard-budget filter eliminated all matching high-risk, long-term candidates that required a larger minimum investment, prompting the system to abstain rather than present an unsuitable financial option
To control hallucinations, the system relies exclusively on verbatim evidence spans extracted directly from the source text, ensuring it never invents a provider, product, return figure, or guarantee. Return types are rigidly classified at extraction so that indicative, variable, or historical returns are always explicitly paired with disclaimers and never presented as guarantees. If evidence for a field is missing or contradictory, the system leaves it safely blank without guessing, and for queries with no supported match, it handles the failure explicitly by abstaining with a clear explanation instead of forcing an unsupported recommendation.
The codebase is written in readable, modular Python that enforces a strict architectural separation between the extraction, retrieval, ranking, and evaluation components. It includes a complete `requirements.txt` alongside reproducible run instructions, and is backed by basic tests and pydantic validation checks to ensure reliable execution.
